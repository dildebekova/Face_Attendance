# Campus — умная посещаемость
Полный исходный проект для локального контролируемого пилота. Интерфейс на русском, камера, регистрация студентов, занятия, журнал, CSV и ручная отметка с причиной.

## Быстрый запуск на Windows
Установите Docker Desktop (Linux containers/WSL2), Git и Python 3.12+. В папке распакованного проекта откройте терминал VS Code:

```powershell
python init_config.py
# Сначала прочитайте MODEL_LICENSES.md:
python setup_models.py --accept-research-licenses
docker compose up --build
```
Откройте **http://localhost:8080**. Введите значение `ADMIN_KEY` из созданного `.env` (не весь файл). Разрешите камеру браузеру. Первая сборка скачивает Python/Node-пакеты и может занять длительное время. Интернет нужен при установке. Для UI используется необязательный Google Font, при отсутствии сети работает Arial.

Остановка: `docker compose down`. Данные PostgreSQL сохраняются в volume. **Не используйте `down -v`, если хотите сохранить данные.** Храните резервную копию `.env`: потеря EMBEDDING_KEY делает шаблоны нечитаемыми. Не отправляйте `.env` в GitHub.

## Что реализовано
- React + TypeScript + Vite: четыре раздела, камера через getUserMedia, понятные ошибки, адаптивный интерфейс.
- Python + FastAPI: API, проверка ключа преподавателя, одноразовые случайные задания (90 секунд), ограничение частоты создания заданий, проверка занятия.
- OpenCV: декодирование, резкость, освещение, размер лица.
- InsightFace SCRFD / ArcFace (`buffalo_l`, detection + recognition): детекция, выравнивание и embeddings. ONNX Runtime CPU выполняет модели.
- MiniFASNetV2 через оригинальный Silent-Face-Anti-Spoofing: PAD на каждом кадре; MediaPipe Face Landmarker: поворот после нейтральных кадров. Нет обхода проверки при отсутствии модели.
- PostgreSQL + SQLAlchemy: студенты, занятия, уникальные отметки; Fernet шифрует embeddings. Исходные кадры обрабатываются в памяти и не сохраняются.
- Ручная отметка с причиной, экспорт CSV, закрытие занятия, удаление студента вместе с шаблоном и отметками.

## Первый сценарий
1. Введите ключ преподавателя. Статус должен стать «Модели подключены».
2. «Студенты»: имя, номер, группа. Проверьте личность и согласие. Включите камеру, нажмите регистрацию, сначала смотрите прямо, затем поверните голову по стрелке. Захватываются 6 кадров.
3. «Занятия»: предмет и **точно такое же** название группы. Откройте занятие.
4. «Проверка лица»: выберите занятие, включите камеру, подтвердите присутствие. Повторная проверка не создаёт дубль.
5. «Журнал»: просмотр, CSV и ручная отметка. После окончания закройте занятие.

## Ограничения — прочитать до использования
Это не Apple Face ID и не готовая промышленная система. RGB-камера не измеряет глубину. PAD и случайный поворот снижают часть рисков, но не гарантируют защиты от видеоподмены, виртуальной камеры, deepfake или инъекции кадров. Сервер принимает кадры от доверенного рабочего места; доказательства их происхождения нет. Работайте под контролем преподавателя на физически защищённом ноутбуке в аудитории. Нельзя считать это удалённым подтверждением местоположения.

Ключ преподавателя даёт полный доступ к данным и изменениям. Он хранится только в памяти вкладки. Не передавайте его студентам. Порт открыт только на 127.0.0.1; backend и БД наружу не опубликованы. Для сети нужны HTTPS, отдельные учётные записи/роли, аудит, управление устройствами, ограничение запросов и проверка безопасности. Для большого внедрения потребуются миграции БД, политика хранения/удаления и резервное копирование.

Модель не обучается заново. При регистрации формируется усреднённый шаблон. Числовые пороги `MATCH_THRESHOLD=0.55`, `MATCH_MARGIN=0.08`, `PAD_THRESHOLD=0.85`, пороги качества/поворота — **начальные гипотезы, не измеренные показатели точности**. На вашей камере откалибруйте по CALIBRATION.md. По умолчанию не выводится выдуманный «процент точности». Решение принимается только среди студентов выбранной группы.

Однопроцессный backend (`workers=1`) и mutex сериализуют inference и задания. Не масштабируйте workers без переноса одноразовых заданий и лимитов в общую БД/Redis. Отметка и закрытие занятия используют блокировку строки занятия в PostgreSQL. Шаблоны не выдаются через API. Имя/группа/отметки хранятся в БД без полевого шифрования.

## Структура
- `backend/app.py` — API, БД, доступ и посещаемость.
- `backend/vision.py` — реальная обработка моделей и проверка последовательности.
- `backend/policy.py` — пороги и неоднозначность.
- `frontend/src/` — интерфейс.
- `setup_models.py` — отдельная загрузка внешних моделей и исходников.
- `init_config.py` — уникальные секреты.
- `compose.yaml` — запуск трёх сервисов.
- `tests/` — проверки логики и API без камеры.

## Проверки
```sh
cd frontend
npm ci
npm run build
cd ..
# В контейнере с установленными зависимостями:
docker compose run --rm -v ./tests:/tests backend pytest /tests -q
```
Тесты API используют SQLite и подменённую vision-функцию **только внутри тестов**, чтобы проверить ошибки, авторизацию и отсутствие дублей. Рабочий сервер использует PostgreSQL и реальные модели. Фактические результаты проверки этой поставки смотрите в VALIDATION.md, MODEL_TEST_RESULTS.json и HTTP_TEST_RESULTS.json.

## Частые проблемы
- «Модели не готовы»: завершите setup_models.py, проверьте папки models и vendor, затем нажмите проверку подключения. Docker должен иметь доступ к папке проекта.
- Камера недоступна: используйте localhost, разрешите камеру и закройте другие приложения, которые её заняли.
- Не узнаёт: ровное освещение, лицо ближе, повторите. Нельзя понижать порог без измерения ошибок.
- Неверный поворот: следуйте экранной стрелке (изображение зеркальное). Проверка направления должна быть проверена на вашей камере в пилоте.
- Установка требует сеть и ресурсы. Начните на 64-битном ноутбуке с 8–16 GB RAM, без обязательного GPU; время обработки зависит от CPU и измеряется отдельно.

Не публиковалось в интернете: поставка предназначена для запуска из ZIP на ноутбуке.

## iPhone и проверка нейросетей
Подключение iPhone к Windows по USB и выбор камеры: **IPHONE_SETUP.md**.
В интерфейсе есть список камер, обработка отключения устройства и кнопка «Проверить камеру и нейросети». При захвате сохраняются пропорции кадра.

Запуск реальных моделей на статическом тестовом изображении внутри контейнера:
```sh
docker compose exec backend python smoke_models.py
```
Это тест выполнения моделей и корректности выходов, не доказательство точности распознавания или защиты от подделок. Результат запуска в среде разработки приложен отдельно, если проверка завершена.
